# 뽀모도로 + 투두리스트 앱 — 바이브코딩 프롬프트

## 사용법
- 1단계 프롬프트: 초기 스펙 검토용 (이미 완료됨, 기록용으로 보존)
- 2단계 프롬프트: 확정된 스펙 기준, Claude Code 등 코딩 AI에 붙여넣어 실제 개발 시작

---

## 확정된 스펙 요약

**세션 복구 & 미니 타이머**
- 새로고침/탭 이탈 시 시작시간 기준으로 재계산해 복구 (setInterval 카운트다운이 아닌 `시작시간 + 목표시간 - 현재시간` 방식)
- 루틴 모드처럼 여러 구간(업무→휴식→업무→휴식...)이 이어지는 긴 세션에서는, 이 공식을 세션 전체가 아니라 **현재 진행 중인 구간(phase) 단위**로 적용한다. 즉 각 구간의 시작시간을 별도로 기록해두고, 복구 시 "지금이 몇 번째 구간의 몇 초째인지"부터 계산한다.
- Document Picture-in-Picture API로 구글 타이머 같은 미니 위젯 제공 (미지원 브라우저는 인앱 플로팅 UI로 폴백)

**세션 상태값**
- `status: completed | skipped | interrupted`
- `completed`: 타이머가 끝까지 진행되어 정상 종료된 경우
- `interrupted`: 진행 중 "중단하기" 버튼을 눌러 중간에 멈춘 경우 (중단 사유 태그 필수)
- `skipped`: 세션을 시작만 하고 실제로 진행하지 않은 채 건너뛴 경우 (예: 홈에서 세션을 열었다가 타이머 시작 전에 취소) — 이 경우 회고 폼은 생략하고 기록만 남긴다

**세션 중단**
- 타이머 화면에 "중단하기" 버튼
- 중단된 세션도 회고 폼으로 연결, 중단 사유 간단 태그(급한 일/집중 안 됨/계획 변경 등) 추가
- 루틴 모드에서 중단된 경우, 중단 시점까지 체크리스트에서 완료 처리된 하위 투두는 그대로 완료 상태로 유지한다 (세션이 중단됐다고 이미 끝낸 항목까지 취소되지 않음)

**일반 모드**
- 투두 1개 선택 → 세션 시작 (25/5 또는 50/10)

**루틴 모드**
- 루틴을 등록, 수정, 삭제 가능
- 시간대(모닝/퇴근/나이트) × 난이도(최대/기본/최소) = 9개 고정 루틴
- 루틴 선택 시 루틴에 포함된 투두 목록이 **하나의 긴 세션**으로 묶여 진행
- 세션 진행 중에는 루틴 안 투두들이 체크리스트 형태로 표시되어 진행 상황 확인
- 회고 시 "이 설정(25/5 또는 50/10)을 유지할지" 질문은 **일반 모드에서만** 노출한다. 루틴 세션은 구간이 여러 개 이어붙은 구조라 단일 세션 타입 선택과 의미가 다르므로, 루틴 모드 회고에서는 이 질문을 생략한다.

**기록 (월간/주간)**
- 월간 기록: 카테고리별 시간을 %로 보여줌, 달력형태로 도장 (30% 이하 아쉬워요 / 30~65% 참 잘했어요 / 65% 이상 최고예요)
- 주간 기록: 카테고리별 시간을 %로 보여줌, 타임블록으로 기록 (5분 단위 × 12블록 = 1시간, 1행 = 1시간, 7열 = 7일)
- MVP 이후 단계(통계 그래프와 함께)에서 구현. MVP 단계에서는 이 화면 없이 회고 히스토리 리스트로 대체한다.

**멀티 디바이스 로드맵**
1. localStorage 기반 로컬 MVP
2. 데이터 레이어 추상화 (`saveTodo()`, `getTodos()`뿐 아니라 `saveSession()`, `getSessions()`, `saveReview()`, `getReviews()`, `saveRoutine()`, `getRoutines()` 등 모든 엔티티에 대해 동일한 방식으로 함수화)
3. Supabase 연동 (인증 + 클라우드 DB)
4. PWA화 (manifest + service worker, 오프라인 대응)

## 1단계 프롬프트 (기록용 — 이미 완료됨)

```
나는 뽀모도로 타이머와 투두리스트를 결합한 웹앱을 만들고 싶어.
아래 스펙을 검토하고, 빠진 부분이나 애매한 부분을 질문해줘.
아직 코드는 작성하지 마.

### 핵심 컨셉
카테고리별 투두 관리 + 뽀모도로 타이머 + 진짜 휴식 유도 + 세션 회고를 통한 
집중력 개선 루프

### 기능 요구사항

1. 투두 관리
   - 카테고리 생성/수정/삭제 (예: 업무, 공부, 개인)
   - 카테고리별 투두 추가/완료 체크
   - 오늘 진행할 투두를 하나 선택해서 뽀모도로 세션에 연결

2. 뽀모도로 타이머
   - 세션 타입 2가지 중 선택: (25분 업무/5분 휴식) 또는 (50분 업무/10분 휴식)
   - 시작/일시정지/리셋
   - 업무 종료 시 알림, 휴식 종료 시 알림

3. 휴식풀 (진짜 휴식 유도)
   - 휴식 시작 시 "휴대폰/웹서핑이 아닌" 활동을 추천 (예: 스트레칭, 눈 운동, 호흡법, 물 마시기)
   - 사용자가 휴식풀에 활동을 직접 추가/삭제 가능
   - 휴식 시작할 때 풀에서 랜덤 추천 또는 직접 선택

4. 세션 회고
   - 뽀모도로 1세션(업무+휴식) 종료 후 평가 폼 표시
     - 집중도 평가 (예: 1~5점)
     - "이 설정(25/5 또는 50/10)을 유지할지" 여부
     - 자유 메모
   - 회고 기록은 누적 저장
   - 최근 회고들을 모아 트렌드를 보여주기 (예: 최근 5세션 평균 집중도, 추천 세션 타입)

5. 멋쟁이 기록
   - 월간 기록은 카테고리별 시간을 %로 보여줌, 달력형태로 도장이 찍힘 (30% 이하 수행 아쉬워요!, 30%-65% 수행 참 잘했어요!, 65% 이상 수행 와! 최고예요!)
   - 주간 기록은 카테고리별 시간을 %로 보여줌, 타임블록으로 기록 (5분 단위*12블록=1시간 단위 1행*1일 단위 7열)
```

## 2단계: 코딩 시작 프롬프트 (MVP 기준, 확정 스펙 반영)

```
React + TypeScript로 뽀모도로/투두 앱의 MVP를 만들어줘.
저장은 우선 localStorage로 하고, 상태관리는 useState/useReducer로 충분해.
단, 나중에 Supabase 연동으로 바꿀 수 있도록 데이터 접근 함수(saveTodo/getTodos,
saveSession/getSessions, saveReview/getReviews, saveRoutine/getRoutines 등)는
엔티티별로 별도 모듈로 분리해서 구현해줘.

### 데이터 모델
- Category { id, name, color }
- Todo { id, categoryId, title, isDone, isSelected }
- Routine {
    id, name,              // 예: "기본 모닝루틴"
    timeSlot: 'morning' | 'leaving' | 'night',
    intensity: 'max' | 'basic' | 'min',
    todoTemplateIds: string[]   // 순서 있는 하위 투두 목록
  }
- RoutineTodoTemplate { id, routineId, title, order }
- PomodoroSession {
    id,
    mode: 'single' | 'routine',
    todoId?: string,          // mode가 'single'일 때
    routineId?: string,       // mode가 'routine'일 때
    completedTodoIds?: string[], // mode가 'routine'일 때, 세션 중 체크된 하위 투두 기록
    type: '25-5' | '50-10',
    startTime, endTime,
    status: 'completed' | 'skipped' | 'interrupted'
  }
- Review {
    id, sessionId,
    focusScore(1~5),
    keepSameSetting?: boolean,   // mode가 'single'일 때만 사용
    interruptReason?: 'urgent' | 'lost_focus' | 'plan_changed' | 'other', // status가 interrupted일 때만
    note,
    createdAt
  }
- BreakActivity { id, title, description, category }

### 화면 흐름
1. 홈: 일반 모드(투두 1개 선택) vs 루틴 모드(시간대×난이도 선택) 진입 분기
2. 뽀모도로 타입 선택 (25/5 또는 50/10) — 루틴 모드에서는 이 단계를 생략하고 루틴에 지정된 기본값 사용
3. 집중 타이머 화면
   - 진행 중엔 방해 요소 최소화한 UI
   - 새로고침/탭 이탈 시 시작시간 기준 재계산으로 자동 복구 (루틴 모드는 구간별 시작시간 기준)
   - "중단하기" 버튼 (중단 시 사유 태그 선택)
   - 미니 타이머(PiP) 전환 버튼 — 이번 MVP에서는 인앱 플로팅 UI로만 구현, 
     실제 Document Picture-in-Picture API는 다음 단계에서 추가
   - 루틴 모드일 경우, 타이머 옆에 루틴 내 투두 체크리스트 표시. 세션이 중단되어도
     그 시점까지 체크된 항목은 완료 상태로 유지
4. 세션 종료(완료/중단 모두) → 휴식 화면 (휴식풀에서 활동 추천). 세션이 'skipped'인
   경우는 이 단계와 이후 회고 단계 없이 바로 홈으로 복귀
5. 휴식 종료 → 회고 입력 (집중도, 유지 여부 — 일반 모드만, 중단 사유(해당 시), 메모)
6. 회고 히스토리 화면 (최근 세션 집중도 추이)

### 이번 단계에서 만들 것 (MVP 범위)
1. 카테고리 + 투두 CRUD (수정/삭제는 다음 단계로 미뤄도 됨)
2. 25/5 고정 뽀모도로 타이머 (시작/일시정지/리셋/중단)
3. 세션 복구 로직 (시작시간 기반 재계산)
4. 루틴 9종 시드 데이터 + 루틴 모드 선택 및 진행 (하나의 긴 세션으로 묶기)
5. 휴식풀 기본 시드 데이터 + 랜덤 추천 UI
6. 세션 종료(완료/중단) 후 회고 폼 + localStorage 저장
7. 회고 히스토리 리스트 (간단한 평균 집중도 표시만)

50/10 옵션 완전 지원, PiP API, 월간/주간 기록 화면과 통계 그래프, Supabase 연동은
다음 단계에서 추가할 거니까 지금은 구조상 확장 가능하게만 만들어줘.
(MVP 단계에서 회고 폼의 "설정 유지 여부" 질문은 일반 모드에만 노출하고,
루틴 모드에서는 표시하지 않아도 돼.)

먼저 폴더 구조와 컴포넌트 트리, 그리고 위 데이터 모델에 대한 TypeScript 타입 정의를 제안하고,
내가 확인하면 그 다음에 코드를 작성해줘.
```

## 루틴 9종 시드 데이터 (참고용)

| 시간대 | 최대 | 기본 | 최소 |
|---|---|---|---|
| 모닝 | 최대 모닝루틴 | 기본 모닝루틴 | 최소 모닝루틴 |
| 퇴근 | 최대 퇴근루틴 | 기본 퇴근루틴 | 최소 퇴근루틴 |
| 나이트 | 최대 나이트루틴 | 기본 나이트루틴 | 최소 나이트루틴 |

각 루틴 안에 들어갈 세부 투두는 개발 전에 직접 리스트업해서
`RoutineTodoTemplate` 시드 데이터로 넣는 게 좋아요. (예: 최소 모닝루틴 = 이불정리, 물 한 잔, 스트레칭 3개만)

## 휴식풀 초기 시드 데이터 (참고용)

| 카테고리 | 활동 |
|---|---|
| 몸 | 스트레칭, 목/어깨 돌리기, 제자리 걷기, 물 마시기 |
| 눈/뇌 | 창밖 보기, 20-20-20 눈 운동, 멍때리기 |
| 호흡 | 4-7-8 호흡, 박스 호흡 |
| 감각 전환 | 손 씻기, 매트에 눕기, 짧은 명상 |

이 표를 BreakActivity 초기 데이터로 그대로 넣으면 됩니다.
